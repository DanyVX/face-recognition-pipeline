# Edge-case traceability

CLAUDE.md section 7: every edge case in `docs/PROJECT_SPEC.md` must map to at least one test, or be
listed as not covered in `docs/LIMITATIONS.md` with a reason. This file is that map. It was written
by reading the spec top to bottom and grepping `tests/` for each referenced test name; it was not
produced by a script, so re-check it when tests are renamed.

**How to read it**
- Test references are `file::test_name` relative to `tests/` (for example
  `unit/test_imageio.py::test_zero_byte_file`). Parametrized tests are listed once by function name.
- **Covered**: a test (or, for benchmark items, a bench script plus its unit tests) exercises the
  case. **Partially**: some aspect is tested, and the note says what is missing. **Not covered**:
  nothing exercises it; the reason is in the note and the item is listed in
  `docs/LIMITATIONS.md` ("Edge cases not covered").
- `[needs_models]` marks tests that are skipped when the model files are absent
  (`tests/conftest.py`); they all live in `integration/test_*_real_model.py`. `[slow]` marks tests
  skipped by default (`-m 'not slow and not gpu'`).
- "Covered" means "a test exists and asserts the behavior", not "the behavior is good". Where a
  test is an observation on one image, the note says so.
- Benchmark rows point at `bench/` scripts. Result files in `results/` are untracked and some were
  being regenerated when this was written; this file makes no claim about their numbers
  (numbers belong in `docs/RESULTS.md`, which is generated by `bench/report.py`).
